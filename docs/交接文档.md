# ProjectOrchestrator 开发者交接手册

## 一、产品概述

这是一个**PMO（项目管理办公室）驾驶舱**，面向企业中台管理层，提供项目健康度监控、里程碑追踪、资源负荷分析等功能。纯前端 SPA + Node.js/Express 后端，数据持久化在 SQLite。

**技术栈：**
- 前端：Vanilla JS (ES Modules)，无框架，HTML 模板字符串渲染
- 后端：Node.js + Express，SQLite（`better-sqlite3`）
- 文件导入：支持 `.csv` / `.xlsx`（通过 SheetJS/XLSX）

## 三、数据流架构

```
服务启动
  └─ app.js: bootstrap() → fetch /api/bootstrap
       └─ 填充 data-store.js 的内存缓存数组
            (projects[], milestones[], allocations[], personInfo[] ...)
  └─ initApp() → shell.js: bindFilters() + bindEvents() + render()

用户操作 → shell.js 事件总线（单个 click/change/input 监听）
  └─ 更新 state（路由/筛选/抽屉）
  └─ render() → 调用对应 routeViews[state.route]() 返回 HTML 字符串
       └─ 各 view 调用 selectors.js 的计算函数获取派生数据
       └─ innerHTML 替换 #view 容器

写操作（修改里程碑日期等）
  └─ mutations.js → fetch PATCH/POST
       └─ 乐观更新内存缓存
       └─ REV_CONFLICT → 触发 pmo:stale 事件 → shell 重新 bootstrap()
```

**多用户同步机制：** `focus`/`visibilitychange` 事件触发 `bootstrap()` 重新拉取，去重间隔 1500ms。文件上传期间 `suppressSyncUntil` 暂停自动同步防止干扰。

## 四、各功能页逻辑

### 1. 执行驾驶舱（`cockpit` → `cockpit.js`）

**入口选择器：** `cockpitMetrics()` in `selectors.js`

显示以下板块：
- **交付信心指数**：绿灯项目数 / 总项目数，RAG 甜甜圈图
- **立即行动 · 风险项目**：已滑点（实际 > 计划）且未完成的里程碑，按滑点天数排序，点击打开项目抽屉
- **交付波次**：30/60/90 天内到期的未完成里程碑数量
- **集中度风险**：Bus Factor=1 项目数、超分配/超负荷人数、高风险关键人员列表
- **业务线健康热力图**：按 `biz` 字段分组的 RAG 统计
- **人力利用率**：低/中/高负荷人员数量分布

### 2. 管理概览（`dashboard` → `projects.js:dashboardView()`）

**入口选择器：** `overviewMetrics()` in `selectors.js`

受全局筛选器（dept/biz/status/health/pm/period）约束。

显示：
- 顶部 headline 条：总项目数、信心指数、需本周决策数、30天里程碑数
- KPI 卡片行：信心指数（vs 上批次 delta）、红灯项目、30天里程碑、超负荷人员、Bus Factor=1
- 需决策风险项目表
- 快速信号面板（RAG 分布甜甜圈 + 波次 + 人力利用率 + 信号指示）
- 项目阶段分布

### 3. 项目里程碑（`projects` → `projects.js:projectsView()`）

核心是**甘特图**，逻辑最复杂：

- **分组**：`groupBy` 支持 `family`（产品族，默认）/ `dept`（部门）/ `biz`（业务线）/ `pm`（项目经理）/ `none`
- **时间粒度**：`granularity` 支持 `week` / `month`（默认）/ `quarter`，表头日期列由 `milestones.js:computeSegments()` 计算
- **排序**：`sortBy` 支持默认 / 滑点天数 / 交付信心 / 项目名称
- **搜索**：`#project-search` 实时过滤项目行（id/name/pm/product/tech 字段）
- **Today 线**：通过百分比定位，`centerTodayInBoard()` 计算水平滚动中心位置
- **甘特条**：每个里程碑渲染为定位在时间轴上的小矩形，颜色按 RAG 状态

**项目抽屉（Drawer）**：
- 点击项目行或任意 `data-open-project` 触发 `openProject(id)`
- 抽屉有 3 个 Tab：里程碑列表 / 评论 / 项目详情
- 里程碑 Tab 支持：
  - 内联修改计划日期（弹出原因弹窗，需填写变更原因）
  - 实际开始/结束日期直接通过 `<input type="date">` 修改
- 评论 Tab：输入框提交评论，调用 `appendComment()`
- 支持手动设置项目健康度覆盖（override）

### 4. 资源总览（`resource` → `resource.js:resourceOverviewView()`）

英雄卡片行：总人数、覆盖系统数、参与项目数、高负荷人员、超分配人员

主内容：
- **系统/平台资源分布**：按 `system` 字段分组，水平条形图，点击可过滤跳转
- **角色构成**：按角色类型汇总投入率
- **超分配人员列表**：Σ工时 > 100%
- **Bus Factor 风险列表**：项目负责人覆盖度

**筛选器**：`resourceFilters`（system/role/outsource/projectFocus/biz/family 等），system→family 级联逻辑在 `shell.js:bindEvents()` 的 change 处理器中。

### 5. 人员 x 项目矩阵（`matrix` → `resource.js:matrixView()`）

交叉矩阵表：行=系统，列=人员，单元格=工时占比，色阶显示负荷。

### 6. 人员负载（`workload` → `resource.js:workloadView()`）

按人员展示工时分配明细，可导出 CSV（`export-workload-csv`）。

### 7. Bus Factor（`busfactor` → `resource.js:busFactorView()`）

项目维度的关键人风险，`busFactorRows()` 计算每个系统负责该系统超过某阈值的人数，<2 为红色风险。

### 8. 人员索引（`people` → `resource.js:peopleView()`）

人员卡片网格，支持姓名/角色/部门实时搜索。点击卡片打开人员抽屉（`openPerson()`）。

### 9. 数据上传（`upload` → `admin.js:uploadView()`）

三种文件类型分别有拖拽/点击上传槽：
- **项目信息 Excel**：解析 → 预览差异（调 `/api/import/project/preview`）→ 确认 → 全量替换
- **里程碑 Excel**：同上，仅支持 xlsx（Excel 序列日期自动转换）
- **资源分配 Excel**：矩阵宽表，第1行=项目分组，第2行=表头

编码自动检测：优先 UTF-8，遇乱码降级 GB18030，支持 UTF-16 BOM。

导入历史记录通过 `/api/import/history` 加载，渲染在页面下方。

导出支持全部数据打包 Excel（`/api/export/all.xlsx`）或分项 CSV。

### 10. 人员配置（`personnel` → `admin.js:personInfoView()`）

表格列出所有人员，支持内联编辑角色/外包状态，以及新增/删除人员。调用 `/api/person-info` REST 接口，写入后乐观更新 `personInfo[]` 缓存。

### 11. 设置（`settings` → `admin.js:settingsView()`）

可配置：延误红灯阈值天数（`delayRedThresholdDays`）、红色逾期天数（`redOverdueDays`）等。通过 `data-settings-path` 属性收集表单值，PUT 到 `/api/settings`，使用乐观并发（rev 字段）防冲突。

## 五、关键机制说明

### 健康度计算（RAG）
- 由 `selectors.js:projectRag()` 计算
- 若项目有手动 override（`projectOverrides` 表），则以 override 为准
- 否则基于里程碑滑点 + 阈值（来自 `appSettings`）自动判断 R/Y/G

### 乐观并发控制
- `settings` 和 `milestones` 写操作携带 `rev` 版本号
- 服务端冲突返回 `{ code: 'REV_CONFLICT' }`
- 前端收到后触发 `pmo:stale` 事件，shell 强制 `bootstrap()` 重新同步

### 里程碑变更日志
- 修改计划日期必须通过 `reason-modal.js` 填写变更原因
- `milestoneChangeLogs[]` 缓存变更历史，在抽屉的里程碑 Tab 中显示

## 六、本地启动

```bash
npm install
node server/index.js   # 启动 Express，默认端口见 server/index.js
# 浏览器打开 http://localhost:<port>
```

数据库文件为 `data/*.db`（SQLite），首次启动自动执行 migrations。
