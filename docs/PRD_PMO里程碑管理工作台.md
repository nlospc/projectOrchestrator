## 1. 背景与目标

### 1.1 背景
PMO 需要在单一视图中横向监控所有在管项目的里程碑健康度。传统甘特图以任务为粒度，信息过载且维护成本高；PMO 真正关心的是**里程碑级别的"计划 vs 实际"偏差**及其对后续节点的传导影响。

### 1.2 产品目标
1. **一屏总览**：以项目为行、时间为轴，展示全部项目的里程碑分段进度。
2. **过程亮灯**：用颜色直接表达每段里程碑的按期/延期状态（绿=按期，红=延期）。
3. **未来预警**：基于"实际完成时间滚动推算"机制，让上游延期自动暴露对下游里程碑的挤压。
4. **轻量维护**：PM 只需维护"里程碑名称 + 计划完成时间 + 实际完成时间"三个字段，无需维护任务级计划。

### 1.3 非目标（Out of Scope，v1）
- 任务级 WBS 管理、资源/工时管理
- 跨项目依赖关系（FS/SS 等链接线）
- 自动从 Jira/钉钉等外部系统同步（预留接口，v2 考虑）

## 2. 角色与权限

| 角色 | 查看范围 | 编辑权限 |
|---|---|---|
| PMO 管理员 | 全部项目 | 项目 CRUD、里程碑 CRUD、归档、配置预警规则、导出 |
| 项目负责人（PM） | 自己负责的项目（可配置为全部可见） | 仅可编辑自己项目的里程碑（名称/计划时间/实际时间） |
| 部门负责人 | 本部门项目 | 只读 + 评论 |
| 管理层 | 全部项目 | 只读 |

> 关键审计要求：**计划完成时间的任何修改必须留痕**（变更前值、变更后值、修改人、修改时间、变更原因必填），防止"改计划消红灯"。实际完成时间修改同样留痕但原因选填。

## 4. 核心功能设计

### 4.1 甘特主视图

#### 4.1.1 左侧冻结列（Frozen Columns）
| 列 | 说明 |
|---|---|
| 状态灯 | 项目级 RAG 灯（计算规则见 4.4），8px 圆点：🟢🟡🔴⚪（⚪=未启动/已归档） |
| 项目名称 | 点击展开抽屉；hover 显示项目编号（如 PV-01）与简述 tooltip |
| 项目负责人 | 头像 + 姓名 |

支持按任意列排序；默认排序：红灯项目置顶 → 按最近延期天数降序。

#### 4.1.2 时间轴区
- **时间粒度**：周 / 月 / 季度 三档切换，默认"月"。
- **今日线（Today Line）**：红色细虚线贯穿全表，始终可见；视图初始定位为"今日居中"。
- **项目时间范围**：每行渲染区间 = 项目计划开始时间 → max(项目计划结束时间, 最后一个里程碑的实际/推算结束时间)。若推算结束时间超出计划结束时间，超出部分底色加红色斜纹，提示项目整体可能逾期。

#### 4.1.3 里程碑分段算法（核心逻辑）

设项目有有序里程碑 M₁, M₂, …, Mₙ，每个里程碑有 `planned_start_date`（计划完成时间，必填）， `actual_start_date`（实际开始时间，选填）， `planned_end_date`（计划开始时间，必填）， `actual_end_date`（实际完成时间，选填）。每段的渲染区间 `[seg_start, seg_end]` 规则如下：

**段起点 seg_start：**
- M₁ 的起点 = actual_start_date IF actual_start_date!=NULL ELSE planned_start_date
- Mᵢ (i>1) 的起点 = M_{i-1} 的 **实际完成时间**（若已填）；否则 = Mi 的 **计划开始时间**

**段终点 seg_end 与颜色：**

| 场景 | seg_end | 颜色 |
|---|---|---|
| ① 有实际完成时间，且 actual ≤ planned | actual_date | 🟩 绿色（按期完成） |
| ② 有实际完成时间，且 actual > planned | actual_date | 🟥 红色（延期完成）； |
| ③ 无实际完成时间，且今日 ≤ planned | planned_date | ⬜ 灰色（未来计划段） |
| ④ 无实际完成时间，且今日 > planned | 今日 | planned 之前为灰色，**planned→今日为红色**（逾期未完成，持续生长直至填入实际时间） |



**滚动推算（预警传导）：** 
当 M_{i-1} 延期（场景②或④）导致 Mᵢ 的 seg_start 晚于原计划，Mᵢ 段被压缩。若 seg_start ≥ Mᵢ 的 planned_date（剩余工期 ≤ 0），该未来段直接渲染为 🟡 黄色预警段，宽度取最小可视宽度，tooltip 提示"上游延期已完全侵蚀本段工期，需重排计划"。

**三个正交编码通道**

| 通道| 编码| 什么取值| 
|---|---|---|
| 色相 Hue|健康状态| 绿=按期 · 红=延期/逾期 · 琥珀=工期被侵蚀预警| 
| 明度Tone| 已确认 vs 预测| 实色=已填实际(现实) · 浅色虚框=未来计划(尚未发生)| 
|  标记/线型| 计划锚点 vs 实际锚点| 虚线+空心◇=计划完成点 · 实线+实心◆=实际完成点| 

**分段交互：**
- 每段中央显示里程碑名称（宽度不足时省略号，hover tooltip 显示全名 + 计划/实际时间 + 偏差天数）。
- 段与段之间渲染 2px 深色竖线作为里程碑节点标记（呼应你的原型图）；节点 hover 显示 ◆ 菱形高亮。
- 点击某一段：抽屉打开并自动滚动定位到对应里程碑。

| 场景 | 条件 | 填充/颜色 | 线型/形态 | 锚点标记 | 说明 |
|------|------|-----------|-----------|-----------|------|
| ① 已完成·按期 | A ≤ P | 实色绿 | P：虚线◇；A：实心◆ | @P、@A | 实际完成不晚于计划，整体绿色闭环 |
| ② 已完成·延期 | A > P | 实色红主体至A  | P：虚线◇；A：实心◆ | @P、@A | 超期完成，整段区间标红 |
| ③ 未来·在轨 |m{i-1}的A结束≤m{i-1}的P结束视为在轨，此时 m{i}无A 且 今日 ≤ P | m{i}的实际开始时间到今日 =绿色 ghost | P：虚框空心◇ | @P | 尚未开始但仍在计划窗口内 |
| ④ 逾期·未填 | 无A 且 今日 > P | P前浅灰，P→今日实色红（生长） | P：空心◇（已越过） | @P + 今日线报警，标 逾期 Nd | 已超过计划时间且未完成，红色动态增长 |
| ⑤ 预警·被侵蚀 | seg_start ≥ P | 琥珀斜纹 ghost | P：空心◇（起点已越过） | @P | 任务起点已晚于计划点，计划被侵蚀/失效风险 |

#### 4.1.4 边界与异常规则
| 情况 | 处理 |
|---|---|
| 实际完成时间早于上一段实际完成时间（乱序录入） | 保存时阻断，提示"里程碑实际完成时间不得早于上一里程碑" |
| 项目无任何里程碑 | 行内显示浅灰整条 + "未配置里程碑"占位文案，状态灯为⚪ |
| 计划完成时间相同的两个里程碑 | 允许，但渲染为最小宽度段并提示重叠 |
| 项目已归档 | 默认隐藏，可通过筛选器"包含已归档"显示，整行降透明度 50% |

### 4.2 侧边抽屉（Drawer）

点击项目行从右侧滑出，宽度 480px，遮罩 8% 黑色，Esc / 点击遮罩关闭。

#### 4.2.1 项目信息卡
项目名称（行内可编辑）、编号、部门、负责人、计划开始/结束时间、项目级状态灯、整体偏差天数（Σ各段延期天数）。

#### 4.2.2 垂直时间线（Vertical Timeline）
- 自上而下按顺序展示全部里程碑，每个节点卡片包含：
  - **里程碑名称**（行内编辑）
  - **计划完成时间**（日期选择器；修改时弹出变更原因必填框）
  - **实际完成时间**（日期选择器，可留空；快捷按钮"今天完成"）
  - 状态徽章：`按期完成` / `延期 N 天完成` / `逾期 N 天未完成` / `未到期` / `工期被侵蚀`
- 节点连接线颜色与甘特段颜色一致，形成垂直版的同构视图。
- **操作**：
  - 任意位置 hover 出现 `+` 插入新里程碑（自动排序校验）
  - 拖拽手柄调整顺序（调整后触发全链路重算与日期合法性校验）
  - 删除（二次确认；已有实际完成时间的里程碑删除需 PMO 权限）

#### 4.2.3 变更历史 Tab
时间倒序流水：`{时间} {人} 将「{里程碑}」计划完成时间由 {旧值} 改为 {新值}，原因：{xxx}`。支持按里程碑筛选。

#### 4.2.4 评论 Tab
轻量评论流，支持 @提及（触发站内/邮件通知），用于延期归因说明与 PMO 质询记录。

### 4.3 筛选、搜索与视图

- **筛选器**（Notion 风格 filter chips）：部门（多选）、负责人（多选）、项目状态灯（红/黄/绿）、时间范围、是否包含已归档。
- **搜索**：项目名称 / 编号 / 负责人模糊搜索，结果行高亮。
- **分组**：按部门 / 按负责人 / 按状态灯分组折叠，组头显示该组红灯数量。
- **已保存视图（Saved Views）**：用户可将筛选+分组+排序组合保存为命名视图（如"我部门的红灯项目"），Notion 式 tab 切换。

### 4.4 项目级状态灯与统计看板

**项目灯计算规则（可由 PMO 在设置中调整阈值）：**
- 🔴 红：存在"逾期未完成"段（场景④），或最近一个完成的里程碑延期 > X 天（默认 7）
- 🟡 黄：存在"工期被侵蚀"的未来段，或最近里程碑延期 1~X 天完成
- 🟢 绿：其余情况
- ⚪ 灰：未启动 / 已归档

**顶部 KPI 卡片条：**
| 卡片 | 内容 |
|---|---|
| 在管项目数 | 总数（环比上月 +/-） |
| 红灯项目 | 数量 + 点击即筛选 |
| 本月到期里程碑 | 数量 + 已完成占比 |
| 平均里程碑偏差 | 全局平均延期天数，趋势箭头 |

### 4.5 预警与通知

| 触发条件 | 通知对象 | 渠道 |
|---|---|---|
| 里程碑计划完成时间前 N 天（默认 3）未填实际时间 | PM | 站内 + 邮件 |
| 里程碑逾期未完成（场景④触发当天） | PM + PMO | 站内 + 邮件 |
| 逾期持续 ≥ 7 天 | PM + 部门负责人 + PMO | 升级邮件 |
| 计划时间被修改 | PMO | 站内 |
| 未来段工期被完全侵蚀 | PM + PMO | 站内 |

每日 09:00 向 PMO 推送《里程碑日报》摘要（红灯清单 + 本周到期清单）。

### 4.6 数据导入导出

- **导出**：当前视图导出为 PNG（甘特截图，汇报用）/ Excel（项目-里程碑明细 + 偏差天数列）。
- **导入**：Excel 模板批量导入项目与里程碑（PMO 权限），导入校验报告。

## 5. 数据模型（简化）

```
Project
├── id, code (如 PV-01), name, department, owner_id
├── planned_start_date, planned_end_date
├── status (active / archived / not_started)
└── created_at, updated_at

Milestone
├── id, project_id, name, sort_order
├── planned_date (必填)
├── actual_date (可空)
└── created_at, updated_at

MilestoneChangeLog
├── id, milestone_id, field, old_value, new_value
├── reason, changed_by, changed_at

Comment / Notification (略)
```

派生字段（不落库，实时计算）：seg_start、seg_end、seg_color、deviation_days、project_rag。

## 7. 验收标准（关键用例）

1. M1 计划 2/15、实际 2/20 完成 → M1 段终点 2/20 红色，2/15–2/20 叠加深红斜纹；M2 段起点自动变为 2/20。
2. M2 计划 3/30，今日 4/10 且未填实际 → 3/30–4/10 渲染红色且随日期增长；项目灯转红；逾期通知已发出。
3. 修改任一计划完成时间未填原因 → 保存被阻断。
4. 上游累计延期使 M3 的 seg_start ≥ M3 计划时间 → M3 渲染黄色预警段并通知 PM。
5. 抽屉内插入/拖拽里程碑后，甘特视图 1 秒内完成重算重绘。
